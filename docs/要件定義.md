## 4. 非機能要件

- フロントエンドとバックエンドは分離（モノレポ構成）
- コンテナ環境（Docker）で動作すること
- サーバーサイドは JS/TS 以外（Python + FastAPI）
- フロントエンドは TypeScript を使用（Next.js 可）
- 設計書（ER図・API仕様書・README）を作成・管理すること
- セキュリティ対策（XSS・SQL injection）を実施すること
- 単体テスト・統合テストを作成すること
- ログ：デバッグログは本番環境で出力しないこと

## 5. 機能要件

### 認証・ユーザー管理

| 機能               | 概要                                                               |
| ------------------ | ------------------------------------------------------------------ |
| 会員登録・ログイン | Firebase Auth によるメール＋パスワード認証（フロントエンドで完結） |
| プロフィール編集   | ユーザー名・アバター画像の更新                                     |

> **補足**：ログイン・会員登録の処理は Firebase Auth がすべて担当するため、バックエンドに `/auth/login` や `/auth/register` のエンドポイントは不要。フロントエンドが取得した Firebase ID トークンを `Authorization: Bearer <token>` ヘッダーでバックエンドに送り、バックエンドはそのトークンを検証するだけ。

### レシピ管理（CRUD）

| 機能                   | 概要                                                   |
| ---------------------- | ------------------------------------------------------ |
| レシピ投稿・編集・削除 | タイトル・材料・手順・画像。自分の投稿のみ編集・削除可 |
| レシピ詳細・一覧表示   | 全レシピ閲覧可能                                       |
| 検索                   | タイトル・材料のキーワードで絞り込み                   |
| 画像アップロード       | Cloudinaryに保存                                       |

## 7. API設計

### ユーザー

> ログイン・会員登録は Firebase Auth で行うため、バックエンドの認証エンドポイント（`/auth/register`・`/auth/login`）は不要。

| メソッド | パス        | 説明                       | 認証                    |
| -------- | ----------- | -------------------------- | ----------------------- |
| GET      | `/users/me` | ログイン中ユーザー情報取得 | Firebase IDトークン必須 |
| PUT      | `/users/me` | プロフィール編集           | Firebase IDトークン必須 |

### レシピ

| メソッド | パス            | 説明                                 | 認証                    |
| -------- | --------------- | ------------------------------------ | ----------------------- |
| GET      | `/recipes`      | レシピ一覧取得（キーワード検索対応） | 不要                    |
| GET      | `/recipes/my`   | 自分のレシピ一覧取得                 | Firebase IDトークン必須 |
| GET      | `/recipes/{id}` | レシピ詳細取得                       | 不要                    |
| POST     | `/recipes`      | レシピ新規投稿                       | Firebase IDトークン必須 |
| PUT      | `/recipes/{id}` | レシピ更新（本人のみ）               | Firebase IDトークン必須 |
| DELETE   | `/recipes/{id}` | レシピ削除（本人のみ）               | Firebase IDトークン必須 |

## 8. DB設計（概要）

### users テーブル

| カラム       | 型           | 説明                           |
| ------------ | ------------ | ------------------------------ |
| id           | UUID         | 主キー                         |
| firebase_uid | VARCHAR(128) | Firebase Auth の UID（UNIQUE） |
| username     | VARCHAR(50)  | ユーザー名（UNIQUE）           |
| email        | VARCHAR(255) | メールアドレス（UNIQUE）       |
| avatar_url   | VARCHAR(500) | アバター画像（Cloudinary URL） |
| role         | VARCHAR(20)  | ロール（`user` 固定）          |
| created_at   | TIMESTAMP    | 作成日時                       |

### recipes テーブル

| カラム       | 型           | 説明                         |
| ------------ | ------------ | ---------------------------- |
| id           | UUID         | 主キー                       |
| title        | VARCHAR(200) | レシピタイトル               |
| ingredients  | TEXT         | 材料                         |
| instructions | TEXT         | 調理手順                     |
| image_url    | VARCHAR(500) | レシピ画像（Cloudinary URL） |
| user_id      | UUID         | 投稿者（FK → users）         |
| created_at   | TIMESTAMP    | 作成日時                     |
| updated_at   | TIMESTAMP    | 更新日時                     |

## 10. Git運用ルール

**ブランチ戦略**

```
main
└── develop
    ├── feature/frontend-pages
    ├── feature/backend-recipes
    ├── feature/auth
    └── feature/docker
```

**フロー**

1. `develop` から `feature/*` ブランチを切る
2. 作業・コミット
3. Pull Request を作成
4. チームメンバー1人がレビュー
5. 確認後 `develop` にマージ
