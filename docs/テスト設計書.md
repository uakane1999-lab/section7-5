# テスト設計書
 
## 1. テスト方針
 
### 目的・品質ゴール
 
| 目的 | 内容 |
|------|------|
| 機能の正確性 | 各APIが設計書通りのレスポンスを返すことを保証する |
| 認証・認可の安全性 | 未認証・他人のリソースへのアクセスが正しく拒否されることを確認する |
| 回帰防止 | 機能追加・修正時に既存機能が壊れていないことを検知する |
 
### カバレッジ目標
 
| 対象 | 目標 |
|------|------|
| バックエンド（Python） | ラインカバレッジ 80% 以上 |
| フロントエンド（TypeScript） | ラインカバレッジ 70% 以上 |
 
### テストピラミッドの考え方
 
```
        /\
       /E2E\         少ない・重要なユーザーシナリオのみ
      /------\
     / 結合   \      API単位の正常系・異常系
    /----------\
   /  単体テスト \   関数・コンポーネント単位で最も多く書く
  /______________\
```
 
- **単体テスト**を最も多く書き、バグを早期に発見する
- **結合テスト**でAPIのリクエスト〜レスポンスの流れを確認する
- **E2Eテスト**は主要なユーザーシナリオに絞って自動化する
---
 
## 2. テスト種別と範囲
 
| 種別 | 対象 | ツール | 担当 |
|------|------|--------|------|
| 単体テスト（BE） | API関数・認証ロジック・Cloudinary処理 | pytest | メンバーA・B |
| 単体テスト（FE） | Reactコンポーネント・API呼び出し関数 | Jest | メンバーC・D |
| 結合テスト | APIエンドポイント全体（DB含む） | pytest + TestClient | メンバーA・B |
| E2Eテスト | ユーザー操作のシナリオ | Playwright | メンバーD |
| 性能テスト | レシピ一覧取得のレイテンシ | k6 | 任意（時間があれば） |
| セキュリティ | 認証・認可・XSS・SQLインジェクション | 手動確認 + OWASP ZAP | 全員 |

### E2Eテスト（メンバーD担当）
 
| ID | シナリオ | 手順 | 期待結果 |
|----|---------|------|---------|
| E2E-001 | 新規ユーザー登録 | 1. 登録画面を開く 2. 必要情報を入力 3. 登録ボタンを押す | マイページに遷移する |
| E2E-002 | ログイン | 1. ログイン画面を開く 2. メール・パスワードを入力 3. ログインボタンを押す | レシピ一覧画面に遷移する |
| E2E-003 | レシピ投稿 | 1. ログイン済みの状態で投稿画面を開く 2. タイトル・材料・手順を入力 3. 画像をアップロード 4. 投稿ボタンを押す | レシピ詳細画面に遷移し投稿内容が表示される |
| E2E-004 | レシピ検索 | 1. 一覧画面でキーワードを入力 2. 検索ボタンを押す | キーワードに一致するレシピのみ表示される |
| E2E-005 | レシピ編集 | 1. 自分のレシピ詳細画面を開く 2. 編集ボタンを押す 3. タイトルを変更 4. 保存ボタンを押す | 変更内容が反映されている |
| E2E-006 | レシピ削除 | 1. 自分のレシピ詳細画面を開く 2. 削除ボタンを押す 3. 確認ダイアログでOKを押す | レシピ一覧から削除されている |
 
### セキュリティテスト
 
| ID | テストケース | 確認方法 |
|----|------------|---------|
| SEC-001 | SQLインジェクション | 検索パラメータに `' OR 1=1 --` を入力してエラーにならないか確認 |
| SEC-002 | XSS | レシピタイトルに `<script>alert('xss')</script>` を入力して実行されないか確認 |
| SEC-003 | 他人のレシピを直接URL指定で編集できないか | 別ユーザーでログインしてPUT /recipes/{id} を叩く |
| SEC-004 | 未認証で保護されたAPIにアクセスできないか | Authorizationヘッダーなしでリクエストを送る |

## 4. テスト環境
 
### 環境の差分
 
| 項目 | 開発環境 | 本番環境 |
|------|---------|---------|
| DB | SQLite（単体テスト） / PostgreSQL（結合テスト） | PostgreSQL |
| 認証 | モック or Firebase（テスト用プロジェクト） | Firebase（本番プロジェクト） |
| 画像 | Cloudinary（テスト用フォルダ） | Cloudinary（本番フォルダ） |
| 起動方法 | Docker Compose | Docker Compose |
 
### テストデータ作成方針
 
- 単体テスト：pytestの `fixture` でテストごとにDBを初期化・クリーンアップ
- 結合テスト・E2E：`backend/seed.py` でテスト用ユーザー・レシピを投入
- 本番DBには絶対にテストデータを入れない

- [ ] 全テストが green（1件もfailしていない）

- [ ] デバッグログが本番環境で出力されないことを確認済み
