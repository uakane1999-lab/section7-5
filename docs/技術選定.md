# 技術選定書
 
## 1. 選定方針
 
本プロジェクトはチーム開発の学習を目的とした課題であるため、以下の優先順位で技術選定を行った。
 
1. **学習コストの低さ** — 4人チームが短期間で実装を完走できること
2. **未学習技術への挑戦** — 課題要件として JS/TS 以外のサーバーサイド技術を採用すること
3. **実務での需要** — 習得した技術が実際の現場でも活かせること
4. **運用コストの低さ** — 無料枠・OSSを優先し、インフラコストを最小化すること

## 2. 技術スタック一覧
 
| レイヤ | 採用技術 | 候補 | 選定理由 |
|--------|----------|------|----------|
| フロントエンド | Next.js 14 + TypeScript | Nuxt3, SvelteKit | チームの既習技術であり、App Router / SSR の学習効果が高い。課題要件でTypeScript必須のため。 |
| バックエンド | Python 3.12 + FastAPI | Go + Gin, Ruby on Rails | 課題要件の「JS/TS以外」を満たしつつ、Python は学習コストが低い。FastAPI は型安全・自動ドキュメント生成（Swagger UI）があり開発効率が高い。 |
| データベース | PostgreSQL 16 | MySQL, MongoDB | RDBMSの中で機能が豊富。JSON型サポートや全文検索など拡張性が高く、実務でも広く使われている。 |
| キャッシュ | Redis 7 | Memcached | レシピ一覧などの読み取り頻度が高いデータをキャッシュし、DB負荷を軽減。課題のADVANCED要件にも合致。 |
| 画像ストレージ | Cloudinary | AWS S3, Firebase Storage | 無料枠が充実しており、画像の変換・最適化APIが標準搭載。SDKも豊富でバックエンドからの連携が容易。 |
| 認証 | Firebase Authentication | Auth0, 自前JWT | Google / メール認証が数行で実装可能。無料枠が十分で、フロントエンドSDKの使いやすさが高い。 |
| コンテナ | Docker / Docker Compose | — | 課題要件。チーム全員が同一環境で開発できるため、「自分の環境では動く」問題を防止。 |
| ホスティング | （検討中） | Vercel + Render, Railway, Fly.io | フロントは Vercel、バックエンドは Render の無料枠が最もコストゼロで構築しやすい。 |
| CI / CD | GitHub Actions | CircleCI, GitLab CI | GitHubと直接統合でき、無料枠が充実。チームが GitHub を使うため導入コストがゼロ。 |
| 監視・ログ | Uvicorn ログ + Docker logs | Datadog, Sentry | 開発フェーズでは標準ログで十分。本番環境を想定する場合は Sentry（無料枠あり）の導入を検討。 |

## 3. 比較サマリ
 
### バックエンド：FastAPI を採用 / Go・Rails を不採用
 
| | FastAPI | Go (Gin) | Ruby on Rails |
|--|---------|----------|---------------|
| 学習コスト | 低 | 高 | 中 |
| 開発速度 | 速い | 普通 | 速い |
| 型安全 | ◎ (Pydantic) | ◎ | △ |
| 自動ドキュメント | ◎ (Swagger) | 要設定 | 要設定 |
| 実務需要 | 高（AI/ML系） | 高（インフラ系） | 中 |
 
→ 短期間での実装完走と学習効果のバランスから **FastAPI を採用**。
 
### 認証：Firebase を採用 / 自前JWT を不採用
 
自前でJWT認証を実装する場合、トークン管理・リフレッシュ・セキュリティ対策など実装コストが高い。
Firebase Authentication はそれらを肩代わりしてくれるため、**認証の本質的な学習よりもアプリ機能の実装に集中できる**点を優先して採用。
 
### 画像ストレージ：Cloudinary を採用 / S3 を不採用
 
AWS S3 は IAM 設定や署名付きURL など設定が複雑。
Cloudinary は無料枠（25GB）で十分かつ、アップロードURLの発行・画像リサイズが簡単なため採用。

## 4. リスクと対応
 
| 技術 | 懸念点 | 緩和策 |
|------|--------|--------|
| FastAPI | チームの Python 習熟度にばらつきがある | 公式ドキュメントが充実。Swagger UI で動作確認しながら進められる |
| Firebase Authentication | Firebase 障害時に認証が全停止する | 開発・デモ環境では許容。本番移行時はエラーハンドリングを追加する |
| Cloudinary | 無料枠（25GB/月）を超えると課金が発生 | 開発中は画像サイズを圧縮してアップロード。容量監視を設定する |
| Redis | キャッシュとDBの整合性が崩れる可能性 | レシピ更新・削除時にキャッシュを必ず invalidate する実装を徹底する |
| Docker | Windows 環境で動作が不安定になることがある | Docker Desktop を最新に保つ。WSL2 を有効化して使用する |
| PostgreSQL | スキーマ変更時のマイグレーション管理 | Alembic を使ってマイグレーションファイルをバージョン管理する |
